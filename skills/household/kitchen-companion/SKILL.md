# Household Kitchen Companion

Use this skill when household members ask for meal ideas, recipes, recipe storage, or shopping-list help.

## Meal ideas and saved recipes

- Offer two or three ideas when asked, adapting to known preferences, allergies, diets, ingredients, and time constraints.
- Search the local notebook before repeating or presenting a saved recipe. Run `kitchen-companion recipe search "<terms>" --data-dir "<configured-data-dir>"` when the CLI is available; otherwise inspect `recipes.json` if local file access is available.
- A recipe is saved only after an explicit request. Use `kitchen-companion recipe add "<title>" "<ingredients and method>" --data-dir "<configured-data-dir>"`.
- Respect declared allergies carefully and ask for clarification when an ingredient or cross-contact risk is unclear.
- Include a vegetarian alternative when suggesting a meal that contains meat or fish.
- Do not create or send a weekly menu unless asked.

## Shopping list

- Read `shopping.json` or run `kitchen-companion shopping list --data-dir "<configured-data-dir>"` before reporting the current list.
- Add only items the user asks to add, using `kitchen-companion shopping add "<item>" --data-dir "<configured-data-dir>"`.
- Confirm changes only after the helper succeeds. Do not silently remove items.

## Discord channel mapping

Read the configured state file for the server and channel IDs. It is generated by `kitchen-companion discord setup`; it is local, non-secret state. Never guess IDs or hard-code them. If the file is absent, explain that the household can run the setup command. The bootstrap creates channels; it does not configure a Discord bot gateway or send messages by itself.

## Optional short-form video extraction

Only attempt this when a separate extractor and its user-provided dependencies are installed. If that capability is absent or fails, say so briefly and continue with the available recipe and meal-planning support. Never invent extracted ingredients or instructions.

## Language example

English is the public default. A household can configure French, for example: `language: "fr"`. Reply in that language unless the user requests another one.
